## What this is

Official site of KD Pixels (Kshitij Deota): Android icon packs, UI design &
front-end development. Static brochure + catalogue + blog (blog sections are
still to be built). The site's job: funnel visitors to (1) Google Play packs,
(2) the future direct-sale store (Lemon Squeezy), (3) freelance/services.

- **Stack**: Astro 5, static output (`build.format: 'directory'`,
  `trailingSlash: 'always'`), vanilla CSS design tokens, no JS framework.
  Deploys: GitHub Pages (repo `kshitijdeota/kshitijdeota.github.io`, CNAME
  kdpixels.com). Local test deploys go to the home webserver (below).
- **Branches**: work happens on `master` locally; pushed to remote branch
  `astro-rebuild` until the cutover to production is approved (pushing
  `master` auto-deploys the OLD Jekyll GitHub Pages workflow to the live
  domain until the Pages workflow is replaced). Tag `pre-astro` marks the
  last Jekyll commit — full legacy lives in git history there.

### Power-loss resilience (this box loses power regularly)

Cyclone/thunderstorm season (500 km out) causes repeated hard power cuts and
unclean shutdowns. Assume any reboot happens **without warning**:

- `kdpixels-dev.service` is `enabled` + `Restart=always` → comes back on its
  own. Safe.
- The static test build lives on disk (`/var/www/dev/kdpixels/`) → survives.
- **`systemd-run --on-calendar` transient timers are wiped by any reboot.**
  Use a persistent unit file in `/etc/systemd/system/` instead:
  `Persistent=true`, `WantedBy=timers.target`, `systemctl enable --now`.
- Long jobs must write atomically. `pull-metrics.mjs` writes
  `metrics.json.tmp` then `rename()`s it, so a cut mid-write cannot leave a
  truncated file that breaks the build.
- After an unclean boot, the 30-second sanity check:
  ```
  systemctl is-active kdpixels-dev.service
  systemctl list-timers --all | grep kdpixels
  journalctl -b -p err --no-pager | tail
  curl -sk --resolve box.local.kdpixels.com:443:192.168.0.131 -o /dev/null \
    -w '%{http_code}\n' https://box.local.kdpixels.com/kdpixels/
  ```

transient retry timer used while waiting is **retired** (it also died on the

```

```

then bring the result back and commit it:

```

```

A full run lists ~39k bucket objects and downloads ~900 monthly install CSVs
(for the lifetime sums) plus a couple of ratings files per app — a couple of
minutes. Nightly CI does this automatically once the repo secret exists.

### Financial reports (earnings / IAP revenue)

`earnings/` and `sales/` objects are **listable but not readable** until the
service account has Play Console's **Account permissions → Financial data →
"View financial data, orders, and cancellation survey responses"**. Symptom:
listing works, `storage.objects.get` returns 403. Owner ticked this on
2026-10-29; it mirrors like the stats grant (minutes → ~24h).

A **persistent** watcher polls for the mirror (`scripts/earnings-try.sh` →
`scripts/earnings-watch.mjs`). Persistent, not transient, precisely because
this box reboots without warning: `systemd-run` timers never come back.
Installed as `/etc/systemd/system/kdpixels-earnings-watch.{service,timer}`
(`OnCalendar=*:0/10`, `Persistent=true`, `WantedBy=timers.target`).

```
ssh jellyfinboxadmin
systemctl enable --now kdpixels-earnings-watch.timer
systemctl list-timers kdpixels-earnings-watch.timer
```

On success the script `systemctl disable --now`s the timer, so it does not
resurrect itself after a later reboot.

Log: `/home/kd/logs/earnings-watch.log`. The earnings archives are **monthly
zips** (`earnings_<YYYYMM>_<id>-<n>.zip`, ~119 of them, newest 202609)
containing transaction-level CSVs — they carry `Product Title`, `Product id`,
`Product Type`, `Sku Id`, `Currency of Sale` and `Amount (Merchant
Currency)`, so **per-SKU units and revenue need no extra permission**. Read
the real header before writing a parser; do not guess the schema.

**Pattern for future waiting jobs**: a systemd timer driving a single-attempt
script — never a long-running background loop in an agent session (those die
with the session and waste tokens). Use a **persistent unit file** enabled into
`timers.target` with `Persistent=true` (see `kdpixels-earnings-watch.timer`),
not `systemd-run --on-calendar`: transient timers are wiped by any reboot and
this box reboots without warning. `scripts/metrics-try.sh` is the retired
transient version and is kept only as a reference.

## Play Store metrics pipeline

- Reports bucket (pinned from Console "Copy Cloud Storage URI"):
  `gs://pubsite_prod_rev_15742151642195349260`
- Auth: service account `kdpixels-metrics@kdpixels-iconpacks.iam.gserviceaccount.com`
  - Key lives ONLY at `/home/kd/.secrets/play-sa.json` on the server
    (chmod 600, owner kd). Never copy keys into this repo (`.gitignore`
    blocks `service-account.json`, `*sa*.json`, `*.pem`).
  - Grant: Play Console → Users & permissions → **View app information and
    download bulk reports (read-only)**, Global. **No GCP project IAM roles
    are needed or wanted** — Play mirrors this grant into the bucket's
    object ACLs.
  - OAuth scope MUST be `https://www.googleapis.com/auth/devstorage.read_only`
    (Google's documented requirement; the Storage SDK's default
    `cloud-platform` scope does NOT work).
- CSV gotchas (verified against live data 2026-10-28): report CSVs are
  **UTF-16 with BOM** — decode by BOM, not utf8. Installs have **no lifetime
  counter column**: `Total User Installs` is deprecated and reads **0** in
  current files, and `Active Device Installs` is *current users on device*
  (Monoic White ≈ 63k) — **not** the store band. The figure that reproduces
  the public band is the **lifetime sum of `Daily Device Installs`** across
  every monthly `stats/installs/installs_<pkg>_<YYYYMM>_overview.csv`
  (Monoic White = 1.33M ⇒ "1M+"). The script stores that as `installs` and
  keeps `installsActive` alongside. Ratings country files use **ISO-2 codes**
  (`US`, `JP`, `IN`) and hold only a few trailing days — a country absent
  from the file genuinely had no ratings that month (e.g. Bubble has no US),
  so `ratingUS` stays null and the US→JP→global fallback applies.
  Ratings count column may be absent in some months — code falls back.
- `pull-metrics.mjs` writes `src/data/metrics.json` → commit it (builds read
  it; pages fall back to curated bands in `apps.ts` while it's a stub).
- CI: `.github/workflows/play-stats.yml` (nightly 03:00 IST) needs repo
  secret `KDPX_PLAY_SA_JSON` = the SA key JSON. Not yet set by the owner.
  NOTE: the workflow currently commits to the branch it checks out; wire it
  to master at cutover.

## Conventions & rules

1. **Internal links/assets must use `p('/path')` from `src/utils/base.ts`.**
   The test build uses `KDPX_BASE=/kdpixels/`; raw `/absolute` paths break
   in the subfolder deploy. Canonical prod URLs in JSON-LD stay hardcoded to
   `https://kdpixels.com/...`.
2. **Never display hard currency (₹/$/€) for Play apps.** Google localizes
   prices per region; the site shows only `priceLabel(app)` —
   "One-time purchase" / "Free" — plus the "local currency on Google Play"
   note. No `priceNote` fields.
3. **Ratings are US/Japan-first.** The apps' audience is ~0.1% India, so
   `headlineRating()` shows US → JP → global → curated fallback, and the
   ingest pulls `ratings_*_country.csv` for US/JP values. Never frame the
   site (pricing, ratings, locale copy) around the India storefront.
4. **Data-driven pages**: new app → add entry in `src/data/apps.ts` (+ package
   id in `play-packages.json`); pages/sitemap/cross-links generate
   automatically. New in-development project → `upcoming.ts` (promote to
   `apps.ts` when it ships on Play).
5. **Design**: all tokens/components in `src/styles/global.css` (dark default,
   light via `[data-theme='light']`, accent `#ff6e40`). The logo is the
   decade-old KD mark (`public/images/logo-mark.png`, chip-mounted in
   header/footer; favicon set is the same artwork) — keep using it; do not
   swap identity assets without the owner's say-so.
6. **App "artwork" cards are gradient placeholders** until real screenshots
   are self-hosted under `public/images/apps/<slug>/`. Do not hotlink
   `play-lh.googleusercontent.com` URLs in production.
7. **Sync before you finish**: after edits, `npm run sync` so the server dev
   copy matches; `npm run deploy-test` when the static build should update.
8. Commit message style: concise imperative, explain why. Pushes go to
   `astro-rebuild` until cutover.
